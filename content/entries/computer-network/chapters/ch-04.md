# 第四章 应用层——DNS与HTTP

底层把包可靠送到对端，应用层才真正面对「人想干什么」。这一层协议离用户最近：邮件、文件传输、网页、视频都各有规矩。本章挑两个撑起日常互联网的枢纽——**DNS**与**HTTP**，看它们如何把底层的传输能力，变成我们鼠标一点就到的网页。

## DNS：互联网的电话簿

人记不住「九十三点dot一百八十四点二百一十六点 thirty four」这样的 IP，却记得住「某搜索引擎点com」。**DNS（域名系统）**干的就是翻译：把域名解析成 IP。它采用层次化、分布式的数据库——根、顶级域、权威服务器各管一段，谁也存不下全网，却能通过链式查询拼出答案。你输入网址，本机先查缓存，未命中就问本地解析器，解析器代你向根服务器问「点com 归谁管」，再层层向下，最终从权威服务器拿到 IP。

> 📝 编者注：DNS 常被忽视，却是互联网最关键的单点之一。一次解析慢，整页都卡在「正在连接」；解析被篡改（DNS 污染），你便可能被骗到假站。它因此也是安全与治理的焦点。

## 递归与迭代的配合

DNS 查询有「递归」与「迭代」两种角色。你的电脑向本地解析器发起**递归**查询，意思是我把全程交给你、你给我最终答案；本地解析器则对外做**迭代**查询，自己一步步问根、问顶级、问权威，把拼来的答案回给你。这种设计把「负担」放在少数解析器上，既减轻每台终端，又靠缓存让热门域名秒回。缓存有时间上限（存活时间），过期再查，以此在「快」与「准」间平衡——域名换了 IP，全球要等缓存老化才统一。

## HTTP：网页怎么取

**HTTP（超文本传输协议）**规定浏览器与服务器如何对话。浏览器发一个「请求」：写明要哪个资源、用什么方法（取、提交等）、附上些元信息；服务器回一个「响应」：带状态码（如成功、找不到、转向）、头部与正文。网页就是由 HTML 这份正文，加上其中引用的图片、脚本，再由浏览器多次 HTTP 取回拼成。早期每取一个资源建一次 TCP 连接，浪费；后来复用连接、并行取，速度大增。HTTP 之上再加加密层，便成更安全的版本，地址栏出现锁形标记。

## 应用层的位置与演化

应用层协议千千万，但都建立在同一套「请求—响应」「客户端—服务器」的范式上，并复用下层的 TCP 或 UDP。它们的演化很快：从静态网页到动态接口，从明文到全程加密，从人点鼠标到程序调接口（应用编程接口）。理解 DNS 与 HTTP，就握住了日常上网的两大命门——「找到地址」与「取回内容」。第四章看完应用怎么用网；第五章回到更硬的议题：开放的网络怎样保证安全、建立信任，又将走向何方。

## HTTP 的演进：从每次重建到多路复用

HTTP 并非一成不变，它的几次大版本更替，主线就是「怎样更少地等待、更充分地用满连接」。早期版本每取一个资源（一张图、一段脚本）就要新建一次 TCP 连接，握手与慢启动的开销让网页加载卡顿；后来允许在一条连接上串行复用多个请求，省了握手却仍要排队。**HTTP/2** 迈出关键一步：把一条连接里的内容切成多个「流」，多个资源的响应可交错发送、互不阻塞，彻底摆脱应用层的队头阻塞，再加头部压缩，页面提速明显。**HTTP/3** 则更进一步，把底层从 TCP 换成基于 UDP 的 QUIC 传输，连连接建立都合并加密握手一步完成，且在某条流丢包时不再拖累整条连接——这对移动网络频繁切换、易丢包的环境尤为有利。版本演进背后，是对「延迟来自哪里」的持续追问：握手、队头阻塞、丢包恢复，每一处被榨干，用户就少等一截。理解这条演进线，便理解为何今天打开一个富网页比十年前快得多，也理解协议层优化如何在用户无感中悄然发生。值得补一句的是，HTTP 之上的加密也已从「可选附加」变为「默认强制」：新版本普遍要求全程 TLS，明文网页被主流浏览器标记为不安全，协议演进与安全加固因此常常绑定推进——更快的同时也悄悄更私密，这种把安全织进默认设计的转向，正是网络工程从「能用就好」走向「安全是底线」的缩影。
