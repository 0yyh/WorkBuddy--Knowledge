# 第二章 局域网与分组交换

第一章留下了「数据怎么在网里流动」的悬念。这一章下到链路层看局域网，再上到网际层看包如何跨越众多网络抵达远端。两条主线交会的，是现代网络区别于老式电话网的根本选择——**分组交换**。

## 局域网：把隔壁的设备连起来

**局域网**覆盖一栋楼或一片园区，典型代表是以太网。链路层给每块网卡烧一个全球唯一的**MAC 地址**，同网内的机器靠它互相认人。以太网早年的「共享总线」像一群人抢同一根话筒，用载波侦听与冲突退避避免同时说活；后来的交换机则聪明地按 MAC 表把帧精准送到对应端口，不再广播扰民。局域网解决的是「同一片区域内、设备怎么直接互送帧」——它管的是邻居，不管远方。

## 从电路交换到分组交换

老式电话网用**电路交换**：通话前先建一条独占端到端的线路，期间别人不能用，哪怕你沉默它也得空着。这对语音尚可，对突发的数据却是浪费——你读网页的间隙，线路却闲置。现代数据网改用**分组交换**：把数据切成定长或变长的小包，每个包独立寻路。链路不再被谁独占，大家的分组像拥堵路段上的车流交替穿行，谁有数据谁就用一下。整体利用率因此飙升，代价是包可能乱序、延迟、丢失，需要上层补救。

> 📝 编者注：分组交换不是「比电路交换更先进」的万能真理，而是针对「突发、容忍延迟、量大」的数据流量做的优化。语音电话若也走分组（网络电话），便继承了抖动与丢包的毛病，要靠额外机制弥补。技术选型永远看流量性格。

## 路由器与逐跳转发

包要跨出局域网、走向世界，靠**路由器**。路由器连接多个网络，手里有一张「该往哪转发」的表（路由表）。每个包到达，路由器读其目标 IP，查表决定从哪个口送出，下一台路由器接着查、再送一程，这叫**存储转发、逐跳跳转**。没有一台路由器知道全程，却靠分布式协作把包送到。路由表靠路由协议在路由器间互相通告拓扑而动态生成，网络某处断了，流量会自动绕行——这种去中心化的韧性，是互联网抗毁的根基。

## 排队、延迟与拥塞

分组交换的副作用是「排队」。当包到达速度超过链路吐出速度，它们要在路由器缓存里排队，产生**排队延迟**；缓存满了便丢包。延迟还有传播（信号跑路的时间）、传输（把包推上链路的时间）、处理（查表的时间）几项。众多流争抢同一瓶颈链路，便成**拥塞**。网络靠传输层（下一章）的反馈机制感知丢包、主动减速，来维持整体通畅。理解排队与拥塞，才能看懂为何「带宽够大仍会卡」——瓶颈常在中间节点的调度，而非两端速率。第二章交代了「包怎么走」；第三章便看传输层如何在这脆弱的 IP 之上，拼出可靠或轻快的端到端传输。

## 地址解析：IP 与 MAC 如何在本地对上号

同一个局域网里，网络层用 IP 地址彼此寻址，链路层却只认 MAC 地址，二者之间必须有一座桥，这就是**地址解析协议（ARP）**。当你知道目标机器的 IP、却不知道它的 MAC 时，便广播一句「IP 是某某的是谁？请报上 MAC」，局域网内对应那台机器收到后单独回信，询问方便把这对映射记进本地的「ARP 缓存」，下次直接查表、不必再广播。它解决的，是「逻辑地址」与「物理地址」两张皮的接缝问题。ARP 看似简单，却是局域网正常通信的前提——没有它，IP 包在链路层就找不到下一跳该封装给谁。也正因它依赖广播与信任，成了局域网攻击的入口：恶意机器可伪造 ARP 应答，谎称自己是网关，从而截获或篡改他人的流量，所以现代网络常以端口安全、动态 ARP 检测等手段加以防护。把 ARP 与前面的交换机、MAC 表放在一处看，才能完整理解「邻居之间到底怎么认人、怎么送帧」这一链路层的核心命题。ARP 的设计也折射出分层模型的巧妙与无奈：理论上 IP 与 MAC 各管各的、互不相干，但现实里每次跨层封装都免不了一次地址翻译，当网络规模从几台机器涨到数据中心成千上万的虚拟接口时，这种「广播找人」的模式便成了负担，于是又催生了靠路由而非广播来定位的替代方案，一个小小的解析协议，就这样牵动了从家庭 Wi-Fi 到云数据中心的不同工程取舍。
