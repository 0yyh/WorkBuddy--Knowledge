万维网诞生时被设计为一个**无主的空间**：开放协议、自由链接、无须许可即可发布。但 Web 的商业史，是一部**平台化**的历史——开放的地基上，长出了少数几座流量巨型建筑。开放与平台化之辩，是 Web 四十年来未曾落幕的元问题。

**张力的结构**清晰可见。协议层（HTTP、HTML）属于公共品：任何公司都必须实现它，谁也无法独占。应用层则不同：搜索引擎、社交网络、电商与短视频平台在各自的领域聚合了海量用户，成为事实上的**入口与守门人**——它们决定什么内容被看见（排序与推荐算法）、商家能否触达用户（应用商店抽成）、以及数据归属谁。平台的网络效应（详见「数字革命」词条）使这种权力高度集中，且天然具有自我强化性。

**批评集中于三点**。其一，**锁定与抽成**：应用商店的三成抽成、平台的算法黑箱，被认为抑制竞争与创新。其二，**数据垄断**：用户行为数据沉淀于平台，形成他人难以复制的护城河，也使隐私成为系统性风险。其三，**公共广场的私有化**：言论的边界由平台规则而非公共程序决定，其正当性备受争议。

**制度与技术的回应**沿两条线展开。制度线：欧盟 GDPR 确立数据可携带权与被遗忘权，《数字市场法》要求「守门人」平台开放互操作、不得自我优待——用反垄断与互操作性给平台「松土」。技术线：去中心化尝试层出不穷——联邦宇宙（Mastodon 等 ActivityPub 生态）、P2P 网络、以及区块链社区主张的「Web3」，都试图把身份与数据主权还给用户。

> 📜 「Web 的设计初衷是让任何人都能自由地创造与链接，而不仅是消费。」 —— 蒂姆·伯纳斯-李对 Web 初心的重申

值得清醒的是：**开放协议从未失败**——每一次平台封闭引发的迁移（如 RSS 订阅、开放 API、跨平台互操作）最终都回归协议层的价值。真正的问题不是「开放 vs 封闭」的二选一，而是如何在平台效率与用户主权之间，找到制度与技术都认可的平衡点。这场辩论没有终局，因为它本质上问的是：数字社会的公共空间，应当如何治理。

## 张力为何是结构性的

开放与平台化之所以长期并存，是因为两者服务于不同的功能。开放协议解决**可达性**：只要实现标准，任何设备、任何组织都能发布与获取信息，这是 Web 之所以成为公共空间的根基。平台解决**可用性**：在信息过载的环境里，用户需要搜索、推荐、支付、评价与信任担保，而这些需要集中投入与统一规则，于是自然催生了平台。

矛盾的根源在于，平台的能力建立在协议之上，平台的权力却倾向于覆盖协议——它希望用户留在自己的界面里，而不是自由跳转。因此每当平台力量过强，生态就会出现「再中介化」的反作用力：开发者寻求绕开抽成的通道，用户寻找不被算法左右的信息源，监管者则用互操作性要求拆解壁垒。

## 三类制度工具

当前的制度回应大致可分三类。**赋权型**（数据可携、被遗忘、知情同意）把控制权交回用户，困难在于个人行使权利的成本高、效果弱。**结构型**（互操作性义务、禁止自我优待、开放侧载）直接改造市场结构，效果更明显，但界定「守门人」与「必要接口」本身就很困难。**规制型**（数字税、内容责任、算法审计）则从外部约束平台的收益与行为。三类工具各有代价，实践中往往组合使用，共同的问题意识是一致的：平台在事实上承担着公共职能，却由私人决策运营。

## 去中心化的可能与限度

技术路线上，去中心化的尝试持续数十年而未中断：早期的邮件列表与 RSS 试图让订阅脱离平台，联邦宇宙以协议互通的多个实例替代单一服务商，点对点网络把存储与带宽分散到参与者手中。这些系统在特定社群中运行良好，却普遍面对三个难题：**体验一致性**（跨实例的功能与规则参差）、**经济可持续性**（缺少广告之外的成熟变现）、以及**治理**（谁来裁决内容与冲突）。

因此去中心化的意义未必在于取代主流平台，而在于保持**可退出性**——只要退出与迁移的成本足够低，平台就必须在设计中顾及用户与开发者的选择权。开放协议与平台权力之间的拉扯，最终要回答的是数字社会公共空间如何治理；这场辩论不会有终局，因为它的答案会随技术与权力格局反复改写。
