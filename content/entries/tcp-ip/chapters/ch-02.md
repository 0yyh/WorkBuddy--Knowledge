## IP 与 TCP：寻址路由 + 可靠传输

TCP/IP 的两大基石是 **IP**（网际层）与 **TCP**（传输层）。一个只管"送到"，一个负责"送好"。

### IP：无连接、尽力而为

**IP**（RFC 791，IPv4；RFC 8200，IPv6）是网际层的核心。它是**无连接、尽力而为**的协议：每个分组独立携带源/目的 IP 地址，各自经不同路径抵达，网络不保证顺序、不保证一定送达、也不保证不重复。

IP 还负责**分片与重组**——当一条链路的最大传输单元（MTU）小于分组时，IP 把它切小，到目的地再拼回，从而让异构网络可以无缝接力。正是这种"不假设底层"的极简设计，使 IP 能跨越以太网、卫星、无线等任何介质。

### TCP：在不可靠之上建可靠

**TCP**（RFC 9293，2022 年取代 RFC 793）在 IP 之上提供**可靠字节流**：

- **三次握手**建立连接，双方确认收发能力与初始序列号；
- 用**序列号与确认**保证有序、完整，丢失则**重传**；
- **滑动窗口**做流量控制，防止快发送方淹没慢接收方；
- **拥塞控制**（慢启动、拥塞避免、快速重传）探测网络容量，防止压垮公共网络。

TCP 因而成为网页、邮件、文件传输等"不容许出错"业务的首选。

### UDP 与 QUIC：另一类取舍

并非所有流量都需要 TCP 的开销。**UDP**（RFC 768）省去连接与重传，头部极小，适合实时音视频、游戏——偶尔丢包比延迟更可接受。**QUIC** 则在 UDP 之上重新实现可靠传输与安全（内置 TLS 1.3），并以多路复用避免队头阻塞，成为 HTTP/3 的底座。

> 📜 「网络只该做一件事：尽力把分组送到。其余的智能，留给两端的主机。」——TCP/IP 的端到端哲学在 IP 与 TCP 的分工里体现得淋漓尽致。
