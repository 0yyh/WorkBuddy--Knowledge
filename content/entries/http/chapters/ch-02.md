## 从 HTTP/1.1 到 HTTP/3 的演进

HTTP 的「语义」三十年来基本不变，变的是「如何在网络上传输这些语义」——也就是**版本只是传输映射**。

### HTTP/1.1：文本与持久连接

**HTTP/1.1**（RFC 9112，源自 1997 年的 RFC 2068/2616）用**纯文本**报文，易读易调试；引入**持久连接**（一个 TCP 连接上顺序发多个请求）避免反复握手。但它有个老问题：同一连接上请求必须串行等待，容易**队头阻塞**。

### HTTP/2：二进制帧与多路复用

**HTTP/2**（RFC 9113，2015 年 RFC 7540 的继任）做了彻底重构：把报文切成**二进制帧**，在一个 TCP 连接上**多路复用**多条流，并行收发不再互相阻塞；用 **HPACK**（RFC 7541）压缩冗余首部。性能大幅提升，但底层仍跑在 TCP 上——一旦 TCP 层丢包，所有流仍要等它重传。

### HTTP/3：搬到 QUIC 上

**HTTP/3**（RFC 9114）把传输层从 TCP 换成 **QUIC**（基于 UDP）。QUIC 在 UDP 之上自己实现可靠、有序与加密，每条流独立——某条流丢包不再拖垮其他流，彻底解决传输层队头阻塞。在丢包严重的移动网络下，HTTP/3 明显更稳更快。

> 📜 「There is a single protocol called HTTP, and it is not versioned.」——2022 年规范重写的核心思想：方法、状态码、首部（RFC 9110）是永恒的，版本只是把同样的请求/响应映射到不同传输的「方式」。
