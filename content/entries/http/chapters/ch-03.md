## 无状态、缓存与 Web 安全

HTTP 的「简单」要靠几个机制来补完：记住会话的状态、别反复搬同样的东西、以及把通道锁起来。

### Cookie：在无状态上维持会话

由于 HTTP 无状态，服务器用 **Cookie**（RFC 6265）记住用户：响应中的 `Set-Cookie` 把一小段状态交给浏览器，之后浏览器对同一域名的每次请求都自动带回 `Cookie` 首部，服务器据此识别会话。它是购物车、登录态、个性化推荐的基础。代价是隐私与跨站追踪问题：第三方 Cookie 可被广告网络用于跨站画像。为此 Cookie 具备若干安全属性——`Secure` 只在 HTTPS 下发送，`HttpOnly` 禁止脚本读取以缓解脚本窃取凭据，`SameSite` 限制跨站发送以缓解跨站请求伪造，`Domain`/`Path` 限定作用范围，`Max-Age`/`Expires` 控制生命周期。

### 缓存：少搬重复的东西

**缓存**（RFC 9111）让响应在浏览器、代理与 CDN 处就近复用，是 Web 性能最关键的一根杠杆：

- `Cache-Control` 声明缓存策略，如 `max-age`（新鲜期）、`no-store`（完全不缓存）、`private`/`public`（是否允许共享缓存）、`s-maxage`（共享缓存专用）；
- `ETag`/`Last-Modified` 提供校验器，缓存过期后客户端带 `If-None-Match`/`If-Modified-Since` 回源询问；
- 资源未变时服务器返回 `304 Not Modified`（无主体），只传首部，省下整份响应体。

缓存必须配合**版本化的 URL** 或「不缓存 HTML」使用，否则会出现「用户始终拿不到新版本」的经典事故。

### HTTPS：把通道锁起来

裸 HTTP 明文传输，可被窃听、篡改与冒充。**HTTPS** 在 HTTP 之下叠加 **TLS**（传输层安全），提供三件事：

- **加密**：第三方看不到传输内容；
- **认证**：服务器用数字证书证明自己是谁（依赖公钥基础设施与 CA）；
- **完整性**：内容中途未被篡改。

TLS 1.3 把握手压缩到一次往返，并只保留具备前向保密性的密钥交换。现代实践还在其上叠加 **HSTS**（强制浏览器此后只用 HTTPS 访问）、**CSP**（限制可执行脚本来源以缓解注入）、**CORS**（受控地放宽同源策略）等首部。今天 HTTPS 已是默认形态，主流浏览器对纯 HTTP 页面标记「不安全」，搜索引擎也给予排序惩罚。

### 攻击面：几个经典问题

把上述机制连起来看，Web 安全的大部分议题都落在几处交界上。**跨站脚本**让攻击者的脚本在受害者浏览器中以站点身份运行，从而窃取凭据或冒充用户，防御靠输出转义与内容安全策略。**跨站请求伪造**不偷凭据，而是诱导浏览器带着已有 Cookie 发出请求，因此 `SameSite` 与一次性令牌是主要对策。**跨站追踪**利用第三方 Cookie 与浏览器指纹把同一用户在不同站点间关联，隐私法规与浏览器淘汰第三方 Cookie 的举措正在重塑广告技术。**降级与中间人** 则由 HSTS 与严格的证书校验来防。这些问题的共同点是：**协议本身没有漏洞，出问题的是「谁有权代表用户发出请求」这一边界。**

### 会话与身份的边界

值得强调的是：Cookie 里的会话标识本身不是身份，而是一把「临时钥匙」。它能被复制、被窃取、被固定——会话固定攻击正是诱导用户使用攻击者已知的标识。因此会话应当可撤销、应设置合理有效期、应在敏感操作时重新认证，并配合 `Secure`、`HttpOnly`、`SameSite` 三重属性。「认证发生在哪一层」是理解 Web 安全的钥匙：TLS 认证服务器，Cookie 标识会话，应用层认证具体用户，三者不可相互替代。

### 缓存的失效与再验证

缓存最大的难点不在命中，而在**失效**。`max-age` 到期后缓存并不删除内容，而是转入「陈旧」状态，需要向源服务器再验证：带 `If-None-Match` 的请求若返回 `304`，缓存就把本地副本的新鲜期续上；若源站不可达，`stale-while-revalidate` 允许先返回陈旧内容、同时在后台刷新。对静态资源（文件名带内容哈希的脚本、样式与图片）通常设长期 `max-age` 并标注不可变，靠改文件名来发布新版本；对 HTML 则常设很短的 `max-age` 或不缓存，以免用户拿不到新版本。**「长缓存加改名发布」** 是当代前端性能的基本范式。

### 三道防线如何协作

把三层机制放进一次典型请求里看，分工就清楚了。**TLS** 负责通道：浏览器验证服务器证书、协商出会话密钥，此后内容不可窃听、不可篡改。**Cookie** 负责会话：服务器通过 `Set-Cookie` 下发一段标识，浏览器在后续请求中自动携带，于是无状态的协议也能关联起同一用户的多次操作。**缓存**负责效率：未变的资源由本地或中间节点直接应答，既省带宽也降延迟。三者彼此独立：关掉缓存不影响安全，Cookie 传递的是标识而非秘密内容，而 TLS 保护的是传输过程、并不保证服务器可信。**理解这套分工，比记住某个具体首部更能应付真实问题。**

> 📝 编者注：HTTP 的安全并非协议自带，而是**叠加**出来的——Cookie、缓存、TLS 各管一段。理解这种「分层补漏」的思路，也就能理解为什么 Web 安全总在打补丁：底层简单，上层负责兜底；而每一层补丁都同时带来能力与负担。
