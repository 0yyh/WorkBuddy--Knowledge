## 无状态、缓存与 Web 安全

HTTP 的「简单」要靠几个机制来补完：记住房子里的状态、别反复搬同样的东西、以及把通道锁起来。

### Cookie：在无状态上维持会话

由于 HTTP 无状态，服务器用 **Cookie**（RFC 6265）记住用户：`Set-Cookie` 把一小段状态交给浏览器，之后浏览器每次请求自动带回，服务器据此识别会话。它是购物车、登录态的基础——代价是隐私与跨站追踪问题（后由 `SameSite`、`Secure` 等属性缓解）。

### 缓存：少搬重复的东西

**缓存**（RFC 9111）让响应在浏览器、代理、CDN 处就近复用：`Cache-Control` 声明可缓存多久，`ETag`/`Last-Modified` 做「是否仍新鲜」的校验，`304 Not Modified` 让未变资源免予重传。缓存是 Web 性能的关键杠杆。

### HTTPS：把通道锁起来

裸 HTTP 明文传输，易被窃听与篡改。**HTTPS** 在 HTTP 之下叠加 **TLS**（传输层安全），提供三件事：

- **加密**：第三方看不到传输内容；
- **认证**：服务器用数字证书证明自己是谁（依赖公钥基础设施与 CA）；
- **完整性**：内容中途未被篡改。

今天 HTTPS 已是默认形态，许多浏览器对纯 HTTP 站点标记「不安全」。

> 📝 编者注：HTTP 的安全并非协议自带，而是**叠加**出来的——Cookie、缓存、TLS 各管一段。理解这种「分层补漏」的思路，也就能理解为什么 Web 安全总在打补丁：底层简单，上层负责兜底。
