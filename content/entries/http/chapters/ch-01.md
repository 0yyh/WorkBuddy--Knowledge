## 请求/响应模型与报文

HTTP 的本质是一次「一问一答」：**客户端发请求，服务器回响应**。RFC 9110 把这套语义从具体版本中抽离出来，成为所有 HTTP 版本共享的核心。

### 请求

一个 HTTP 请求由四部分构成：

- **方法**：表达操作意图，最常见的是 `GET`（取资源）、`POST`（提交数据），另有 `PUT`/`DELETE`/`HEAD`/`PATCH` 等。
- **目标**：通常是 URL（RFC 3986），标识要操作的资源。
- **首部（Headers）**：携带元数据，如 `Host`、`User-Agent`、`Accept`、`Content-Type`。
- **主体（Body）**：可选，POST/PUT 时放要提交的数据。

### 响应与状态码

服务器返回一个**状态码**表明结果，三位数字分五类：

- **2xx 成功**：`200 OK`、`201 Created`；
- **3xx 重定向**：`301` 永久迁移、`304` 未修改（命中缓存）；
- **4xx 客户端错误**：`400` 坏请求、`403` 禁止、`404` 未找到；
- **5xx 服务端错误**：`500` 内部错误、`503` 不可用。

首部如 `Content-Type`、`Content-Length`、`Cache-Control` 描述响应主体的格式与缓存策略。

### 无状态与首部

HTTP 被设计为**无状态**：每个请求相互独立，服务器默认不记得上一个请求是谁。这带来极大的可伸缩性——任何一台服务器都能处理任何请求。需要「记住用户」时，状态被显式地放在首部（如 `Cookie`）或后端，而非协议本身。

> 📝 编者注：正因为「无状态 + 文本可读的首部」，HTTP 才如此容易被调试、被代理、被缓存。简单，是它战胜更复杂协议的根本原因。
