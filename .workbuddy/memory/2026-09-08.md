### Bug A：内容 404 —— 点号目录被双重丢弃（重要坑）
根因是 `.index` 这个**带前导点的目录名**，会被两道过滤各丢弃一次：
1. Capacitor 的 `cap sync`（webDir → `assets/public`）用 `dot:false` 的 glob，跳过点号目录；
2. **AGP 的 `MergeAssets` 同样丢弃点号目录**。曾尝试在 `app/build.gradle` 加 gradle task 把
   `dist/content/.index` 重新注入 `src/main/assets/public/content/.index`——task 确实执行了、文件
   也确实落在源 assets 目录，但 `mergeDebugAssets` 产物里依然没有。**打补丁绕不过去，必须改名。**

**最终方案：在"搬运进 web 产物"这一步改名 `.index` → `index`**
- `scripts/copy-content.mjs`：`copyDir('.index', 'index')`（copyDir 增加 destRel 参数），头部注释写明原因
- `apps/web/src/lib/loader.ts`：5 处 fetch 路径改 `index/...`（manifest / taxonomy / title.json / 检索分片 / 词条分片）
- `apps/web/src/lib/content.ts`：`index/tracks.json` + 错误文案
- `apps/web/src/components/CategoryTree.tsx`、`types.ts`：仅文案/注释，一并同步
- 移除先前加的 gradle 注入 task（已无用）

**刻意未改动** `packages/core` 与 `packages/cli`：它们内部仍产出 `.index/`（builder 的
`files['.index/...']` 键被 47 个 core 单测断言），改名只在"投递给 web/Android"的边界发生，
避免动到已通过的测试。

验证：APK 内 `assets/public/content/index/` 共 28 个文件（manifest / taxonomy / tracks /
title.json / 16 个检索分片 / 7 个词条分片），打包 JS 中已无 `.index/`，残留检查通过。

2. **阅读页系统返回直退桌面（高危，曾两轮修）**：根因=冷启动/深链直进时是单格 reader 栈，物理 back 直接退 App。最终正确修法（`EntryReaderPage.tsx`+`router.tsx`）：仅当 `canBackToCover(slug)` 为假时 `history.replaceState('#/entry/{slug}')` 把当前 reader 原地变封面 + `history.pushState('#/entry-reader/{slug}')` 封面之上放回 reader（两者不触发 hashchange，URL/内容恒为 reader），`stackFixedRef` 只重建一次，再 `markReaderFromCover(slug)` 同步会话轨迹先于 useHashRoute 基线。栈=[封面,reader]，back 恰好落封面。⚠️**不要**用"pushState 占位"（会把封面压到 reader 上方导致 back 只弹回 reader 封面永不出现 + URL 不一致 + ← 死键）。
3. **阅读背景只改小卡**：根因=`.reader-root` 声明 `--reading-bg:#fff` 位于 `.reading-bg-*` 之后同特异性，覆盖主题变量 → 恒白。修：`.reader-root` 只消费 `var(--reading-bg, #fff)` 不再声明默认，主题类维持声明变量；补 `color-scheme: light` + `.reader-root.reading-bg-dark{color-scheme:dark}`。
4. **阅读 chrome 太电影**：顶仅 ← + `reader-pos-mini`(i/N) + 目录；底仅 上/下章胶囊 + 中间 `reader-tools`(目录/夜间/设置 3 按钮)；删进度条/大标题；浮层纯色半透明（dark 用 rgba(28,28,28,.94)）非磨砂。
5. **搜索整 section 未隐藏**：`SearchPage.tsx` `const showTitleSection=(!full||groups.length===0)&&titleHits.length>0` + 条件渲染；full 命中≥1 时标题 section 完全不渲染。

## 返回"回首页+双击退出"失效的真根因（23:30）
- 反馈：滑动返回应逐级回首页 + 首页双击退出，又失效。
- 真根因：MainActivity.onBackPressed 用的是「两段式」——先 `WebView.canGoBack()==true` 就直接 `wv.goBack()` 并 return；只有无可回退历史时才 evaluateJavascript 问 Web 层 `window.__pksHandleBack()`。而 SPA 是 hash 路由，首页通常不是 WebView 历史栈底（用户浏览过 browse/cover/其它 tab），canGoBack 恒 true → native goBack 抢先，JS 的 `handleNativeBack`（阅读页→封面、逐级回退、首页双击退出 toast）从未被调到 → 功能看似失效。
- 修复①(MainActivity.java onBackPressed)：删掉 canGoBack/goBack 抢先分支，返回**一律** evaluateJavascript 调 `window.__pksHandleBack()` 让 JS 全权裁决；JS 返回 true=已处理（native 不动），false=首页确认退出才 `super.onBackPressed()`。
- 修复②(router.tsx useHashRoute)：原来只监听 hashchange；返回驱动 `history.back()` 在部分 WebView 只派发 popstate，补监听 popstate，保证路由一定随地址刷新。

## 章节进度条卡在最右（23:5x，桌面 web 复验发现）
- 反馈：阅读页底部章节进度滑杆不随阅读位置变化，始终停在最右（100%）；要求进度匹配滚动位置，且拖动滑杆要跳到对应位置。
- 真根因：滑杆 value = chapterScrollPct，由 scroll 监听算 `(scrollTop)/(scrollHeight-clientHeight)*100`；当 `max<=0` 时按设计取 100%。而 `.reader-root` 是 `position:fixed; inset:0`，但其祖先 `.app-main`（`AppShell.tsx:95`）带 `backdrop-filter`（styles.css:342）→ **backdrop-filter 会建立 containing block**，使 fixed 元素的尺寸锚定到 `.app-main` 而非视口；`.app-main` 在 is-reader 时仍按整页文档流撑高（AppShell 注释明确"滚动在 window，app-main 无 overflow"），于是 `.reader-root` 被撑到整页高度，内部 `.reader-scroll`（absolute inset:0）随之变高 → 正文不再溢出 → `scrollHeight-clientHeight<=0` → 滑杆恒 100%。
- 修复：`EntryReaderPage` 把整棵 `.reader-root` 用 `createPortal(..., document.body)` 渲染到 body 直接子节点，彻底脱离 `.app-main` 的 containing block；`position:fixed` 重新锚定视口，`.reader-scroll` 回到视口高度可正常滚动，滑杆联动 + 拖动跳转（onInput `scrollTo`）恢复。React context 经 portal 透传，`useStation()` 不受影响。
- 校验：`tsc -p tsconfig.json --noEmit` 通过（EXIT 0）。同一份代码对 Android WebView 同样生效（下次 cap sync + assembleDebug 即含此修复）。
- 注意：`.reader-root` 移出 `.app-shell` 后，`.app-shell.is-reader` 隐藏 header/tabbar/footer 的规则仍作用于 app-shell 自身（与 portal 无关），阅读时外壳照常隐藏。
