## 三次返工（决定性根因）：`WebView` 根本没有 `setCustomSelectionActionModeCallback`

- **真根因（务必牢记——前两轮全错在此）**：`android.webkit.WebView` **没有** `setCustomSelectionActionModeCallback` 这个方法，它是 **`android.widget.TextView`** 的 API。
  - 验证方式：`"D:/JDK/jdk-19.0.1/bin/javap.exe" -classpath "D:/Android SDK/platforms/android-35/android.jar" android.webkit.WebView` → 输出中**无任何** `*Selection*` / `*ActionMode*` 成员（android-34 同样）。注意 javap 的 `-classpath` 必须用 **Windows 风格路径**（`D:/...`），用 `/d/...` 会报「找不到类」。
  - 后果：所有基于该方法的「修复」（尤其**反射**调用）必然抛 `NoSuchMethodException`，又被 `catch (Exception ignored)` 吞掉 → 回调**从未安装** → 系统划词栏一直出现。这也解释了当初**直接调用**它会编译报「找不到符号」。
  - 教训：**反射调用一个不存在的方法会静默失败**，比编译期报错更危险；`catch (Exception ignored)` 是帮凶。
- **正确修法（已实施）**：WebView 上唯一可用钩子是覆写 **`startActionMode(ActionMode.Callback,int)`** 与 **`startActionModeForChild(View,ActionMode.Callback,int)`**。
  - 注：`startActionModeForChild` 声明在 **`ViewGroup`**（不是 View），WebView 经 AbsoluteLayout 继承自 ViewGroup，故 `@Override` 合法。
  - `TYPE_FLOATING` 时**绝不 `return null`**（null 会让 WebView 清除选区 = 之前「选不成字」），而是传入 `SUPPRESS_FLOATING` 回调：`onCreateActionMode` 里 `menu.clear()` 且 **`return true`**（true → ActionMode 成立 → 选区与手柄保留；菜单为空 → 工具栏无按钮可画 → 不可见）；`onPrepareActionMode` 再 `menu.clear()`。
  - `MainActivity.onActionModeStarted` 兜底 `mode.getMenu().clear()`，**绝不 `finish()`**（finish 会清选区）。
- **改的文件**：`PksWebView.java`（重写）、`MainActivity.java`（删反射死代码 + 加兜底）。
- ⚠️ **验证假阳性坑**：APK 的 `classes.dex` 里若出现字符串 `setCustomSelectionActionModeCallback` 属**正常**——那是第三方库（AndroidX/Material）的方法名字符串池，紧邻 `setCustomContentView` / `setCustomHeadsUpContentView` / `setCustomSizePreset`。我们自己的类在 `classes3/4.dex`，对它的引用数为 **0**。

## 根因定位：App 内容更新「无法连接更新源（Failed to fetch）」
- **根因 = WebView 混合内容拦截**。App 页面 origin 是 `https://localhost`
  （`capacitor.config.ts` 的 `server.androidScheme:'https'`），更新源是 `http://192.168.x.x:8080`
  （明文）。https 页面拉 http = 混合内容，Android WebView 默认 `MIXED_CONTENT_NEVER_ALLOW`
  → 直接拦断，`fetch` 抛 `TypeError: Failed to fetch`。
- **源码证据**：`Bridge.java:598` 仅当 `config.isMixedContentAllowed()` 才
  `setMixedContentMode(ALWAYS_ALLOW)`；`CapConfig.java:46` `allowMixedContent = false` 默认，
  键名 `android.allowMixedContent`（`CapConfig.java:279-282`）。
- **修复（勿删）**：`apps/web/capacitor.config.ts` 加 `android: { allowMixedContent: true }`。
- **关键区分**：`AndroidManifest.xml` 的 `usesCleartextTraffic="true"` 是**系统网络栈**那道门，
  **不能**打开 WebView 混合内容开关——两道独立的门，缺一不可。
- **为何浏览器正常**：浏览器**顶层导航**到 http 允许；App 是 https 页面里 **fetch 子资源**。
- **CORS 已由 `scripts/serve-lan.mjs` 处理**（`Access-Control-Allow-Origin:*` + OPTIONS 204）；
  若换别的静态服务器（如 `python -m http.server`）会复现同样文案，但根因不同。
