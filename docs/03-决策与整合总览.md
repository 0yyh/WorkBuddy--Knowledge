## 2. 核心模型：两轴知识组织

- **分类轴（树形）**：回答"属于哪个领域"，由 `taxonomy.yaml` 驱动，L1/L2/L3。
- **顺序轴（Track，线性）**：回答"按什么次序学"，一个词条可同时出现在多条序列。
- 两轴**正交**：词条 =（分类坐标，序列坐标）。改动一条不影响另一条。
- **类目可扩展**：新增 L1 学科 = 改配置 + 加目录，**零代码改动（<1h）**，代码中禁止 `if (学科===...)` 分支。
- **六大 L1 排序策略**：历史=chronological 双轨 / 哲学=思想史时序 / 科学=difficulty 难度递进（含心理学分支）/ 经济学=dependency 依赖序（含金融子类）/ 政治理论=school+时序。
- **历史双时间线**：世界史 W01–W10、中国史 C01–C13，约 200 词条严格按年代编号；手机端单轨切换，桌面端（≥1024px）并列双轨共享时间刻度 + 交叉连线（"1840 鸦片战争 vs 英国完成工业革命"对照）。数据零冗余，靠 `timeline:[china,world]` + `sort_date`。
- **边界**：顺序仅用于排列与导航，引入"已学/未学/完成度/进度条"等进度追踪——用户已明确拒绝。

## 4. 技术选型要点（架构设计 §1/§2）

- **存储**：不引入数据库。正文=只读文件（VFS Overlay：随包 `AssetVFS` + 导入 `DocsVFS` 叠加 + 墓碑机制）；索引=构建期产出的分片 JSON/bin，运行时载入 Web Worker 内存；用户数据=极小 KV。
- **搜索**：自研 **CJK bigram 倒排 + BM25**，分 16 片；150 万字索引 ≈3–6MB（压缩后），P95 查询 ≤80ms；L1（title+alias+summary，400KB）0.3s 就绪兜底，L2 全文后台 1.5–2.5s。MiniSearch 保留为可切换 fallback。
- **长文**：≤20k 字整章直渲染；>20k 走 **chunk 化挂载**（8k 字/块 + 占位撑高 + IntersectionObserver 装卸 + AST LRU(30)），**不用虚拟滚动**（保护 Ctrl+F/跨屏选中/锚点）。
- **AI 管线**：跑在 **Node CLI**；网页仅做 Backlog + 审校工作台，写 jobs 文件交 CLI 消费。**公版原文不调 LLM**（直接抓取→切分→落盘，LLM 用量降 95%），LLM 仅做导读/难句注释/顺序草案。断点续传基于 Section 级游标 + 原子写（中断最多丢一章）。
- **包体**：150 万字纯文本 ≈5MB；随包索引 zip 后 ≈2MB。
