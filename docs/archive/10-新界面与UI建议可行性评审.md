## 一、总体结论

1. **外部建议文档的技术栈假设错误**：它按 React + MUI 6 + Tailwind 3 + Framer Motion + React Router 写方案，但本仓库实际是 **React 18 + Vite 5 + TypeScript + 纯 CSS（无 Tailwind/MUI/Framer Motion）**，且使用自研 hash router。因此文档里大量依赖这些库的写法不能直接落地。
2. **不过，截图反馈和交互思路很有价值**：尤其是「确认弹窗全中文」「看过按日期分组」「首页续读卡片」「类目计数 bug」「设置页 List 样式」等，都可以在当前栈内用纯 CSS / 已有组件实现，改动量可控。
3. **当前 App 已经做对了很多**：阅读器沉浸手势、底部 Sheet 设置、主题色板、字号/字体/行距/对齐、目录搜索、时间线双轨等，已经具备基础阅读 App 的完整闭环。外部文档把这些当成「未做」来批评，部分是因为作者没拿到当前源码。

## 三、从截图里看到的真实问题

### 3.1 首页类目计数不一致（你提到的 bug）

**现象**：
- 首页 L1 卡片「历史 28 词条」，展开后 L2「历史方法与概念 1」下面没有任何子项。
- 部分 L2/L3 展开后的数字加起来和 L1 卡片对不上。

**根因**：`apps/web/src/state/AppContext.tsx:55-74` 的 `buildCategoryViews` 用递归计数：

```ts
const total = (node.entrySlugs?.length ?? 0) + children.reduce((sum, c) => sum + c.count, 0);
```

也就是说，一个节点的 `count` = **直接挂在它下面的词条数** + **所有子孙节点的词条数**。问题出在两类节点：

1. **有词条但无子节点的 L2/L3**：例如「历史方法与概念」自身直接挂了 1 个词条，但下面没有 L3。展开时只渲染 `l2.children`，所以下面为空，但头部仍显示 `1`。
2. **L1 卡片数字包含直接归属词条**：L1 的数字是整棵子树的总和；展开后用户看到的是 L2/L3 的分布，如果某些 L2 自身还直接挂了词条，可见数字之和会小于 L1 卡片数字，造成"对不上"的观感。

**建议修复方向**（只做分析，不落地）：
- 方案 A（最小改动）：在 `CollapsibleCategoryTree` 里，对 `count > 0 && children.length === 0` 的 L2 节点，展开时显示一行「该分类下 x 条词条」或让 L2 头部本身可点击跳转到 `/browse/:id`。
- 方案 B（彻底）：不再把「直接归属词条」算进父节点 count，只显示本层直接 count；L1 卡片显示的是子孙总和，需要额外标注。
- 方案 C（折中）：保留当前 count，但在 L2 头部右侧区分「自身 x / 子类 y」，例如 `1 / 0`。

### 3.2 确认弹窗出现英文 CANCEL / OK

截图里「清空阅读历史」「清除续读位置」都用了 `window.confirm(...)`，按钮是系统原生「CANCEL / OK」。

**建议**：换成自定义 Dialog 组件，文案用「取消 / 确认」，危险操作「确认」用红色。零依赖，纯 React + CSS。

### 3.3 「看过」页面信息密度高、缺少分组

当前是单一列表，只有词条名 + 相对时间。没有进度条、没有按日期分组、没有清空入口。

**建议**：按「今天 / 昨天 / 本周 / 更早」分组，每组标题吸顶；每项加阅读进度条；顶部或底部加清空按钮（弹自定义确认框）。

### 3.4 设置页控件「原生感」强

截图里设置页用 `Segmented` 一排胶囊 + `ColorSwatches` 色块，整体还可以，但：
- 分组标题不够清晰；
- 数据管理区没有危险区视觉（红色描边/底色）；
- 版本号左对齐，建议居中。

**建议**：纯 CSS 升级，用 List item 样式（左侧图标/名称 → 右侧当前值 Chip / 箭头），危险区加红色。无需新库。

### 3.5 词条详情页信息堆砌

当前布局从上到下：badge + 标题 + 4 格元数据 + 摘要 + 类目 + 章节目录 + 相关词条 + 开始阅读按钮。

**建议**：
- 把标题 + 原名/副标题 + badge 做成 Hero 区，字号拉大；
- 元数据 4 格改成更紧凑的横排；
- 「开始阅读」固定在底部胶囊按钮（当前已经是底部，但可优化为 sticky）。

## 五、我的综合建议（不依赖外部文档的栈）

基于当前仓库约束和截图反馈，我认为真正值得优先做的不是文档里那些 MUI/Framer Motion 大改，而是下面这组「零依赖、体验质变」的小而精改动：

### P0（体验质变，建议先干）
1. **自定义确认弹窗**：替换所有 `window.confirm`，按钮用「取消 / 确认」，危险操作确认按钮红色。这是截图里最明显的「不精致」点。
2. **修复首页类目计数 bug**：对无子节点但有词条的类目，展开时显示「该分类下 x 条词条」或让该节点可点击跳转。
3. **看过页按日期分组 + 加进度条 + 清空入口**：把单一列表改成「今天 / 昨天 / 本周 / 更早」分组，空态/清空确认都补齐。
4. **首页顶部加续读卡片**：取 `lastReadSlug`，显示「继续阅读《xxx》」+ 进度，点击进入阅读页。

### P1（体验打磨）
5. **搜索页升级**：搜索栏加清除按钮、结果关键词高亮、补历史搜索 / 空态。
6. **词条详情 Hero 区**：标题放大、元数据更紧凑、开始阅读按钮 sticky 胶囊优化。
7. **设置页 List 化**：分组标题更突出、选项行左图标右箭头、数据管理危险区红色。
8. **目录面板拖拽关闭 + 当前章「读到这里」标记**。

### P2（大投入 / 需要新增依赖）
9. **导航重构为「首页 / 搜索 / 看过 / 我的」**：把设置收进「我的」，新增书架/收藏。需要数据层和页面。
10. **系统亮度调节**：需要安装 `@capacitor/screen-brightness`。
11. **状态栏透明沉浸**：需要安装 `@capacitor/status-bar`。
12. **仿真翻页 / 横向时间轴缩放**：投入大、收益不明确，建议最后评估。

## 六、外部文档里可以直接忽略的部分

- 所有依赖 MUI/Tailwind/Framer Motion/Google Fonts 的具体代码片段。
- 「页面切换水平滑动 + 淡入」：自研 hash router 不支持 `useLocation` + `AnimatePresence`。
- 「字体统一用 Noto Serif SC / Source Han Serif SC」：离线无法加载，除非你把完整字体文件打包进 APK（会显著增大体积）。
- 「虚拟滚动 react-window」：当前 84 词条 / 430 章，本地渲染不卡，没必要引入依赖。
- 「动态取色 / Material You」：P2 噱头，当前版本不需要。
