## Part 2 · 高危易碎点 Top 清单

> 排序依据：**(a) 被重构动作打断的概率 × (b) typecheck/test 能否捕获**。标注 `🔴 typecheck 不可见` 的项，即"编译器完全查不到，只有跑起来才炸"。

### 🔴 Top 1 · 12 处运行时 fetch 路径字符串——类型系统与测试全部覆盖不到

- **形态**：`lib/loader.ts:108,155,156,157,168`、`lib/content.ts:102,129,166,167,192`、`lib/cover.ts:12`、`lib/dict.ts:28` 中全部是**模板字符串拼接**（如 `fetchText(\`entries/${slug}/entry.md\`)`）。
- **为何危险**：TS 只校验 `string` 类型合法，**不校验字符串内容是否指向真实资源**。移动 `public/content/index/` → 编译全绿、`vitest` 全绿、`vite build` 全绿，**只有浏览器打开才 404**。
- **雪上加霜**：其中 3 处有 `catch → 静默降级`（`cover.ts:14` 返回 `null`、`loader.ts:124` 吞掉分片错误、`dict.ts:44` 返回 `null`），用户看到的只是"好像没词典 / 没详情图"，**没有任何报错**。
- **兜底**：`CategoryTree.tsx:14`、`Home.tsx:87`、`TimelinePage.tsx:112`、`content.ts:215` 里有 4 处 UI 文案提示，可作为人工巡检锚点。

### 🔴 Top 2 · `.index` → `index` 改名约定，横跨 4 个环节，**断任一环即 404**

| 环节 | 位置 | 作用 |
| --- | --- | --- |
| ① 构建产出 | `index/builder.ts:241-286` | 一律写 `.index/` |
| ② 改名投递 | **`copy-content.mjs:51`** | `.index` → `index`（去前导点） |
| ③ AGP 过滤 | **`app/build.gradle:16`** 的 `ignoreAssetsPattern '.*'` | 默认丢弃点号资源（历史事故根因，见 `REPORT-2026-09-10-content-structure-and-ota.md`） |
| ④ 运行时读取 | `loader.ts` / `content.ts` / `cover.ts` 全部按 `index/` | 一致才能取到 |

- **危险点**：这个约定的唯一说明在 `copy-content.mjs:13-19` 和 `app/build.gradle:56-61` 的**注释**里；注释一旦在重构中被"顺手删掉"，下一个人会以为可以改回 `.index`，然后 Android 端静默全崩。
